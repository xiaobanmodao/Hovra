# Hovra 稳定滚动恢复设计

## 目标

在不破坏当前光标移动、左键、右键、长按和张掌停止稳定性的前提下，恢复一个可主动进入、可预测退出、不会抢占其他动作的纵向滚动手势。滚动继续使用已有的本机 Electron/RobotJS 通道，不新增权限、网络请求或摄像头数据保存。

## 用户手势

滚动姿势为：食指与中指伸直，无名指与小指收拢，拇指不与食指、中指或无名指捏合。用户保持该姿势后上下移动整只手，页面随手掌纵向位移滚动。

选择该姿势的原因：

- 与拇指加食指左键、拇指加中指右键在形状上互斥；
- 与四指全部伸直的张掌停止互斥；
- 只看两根指尖不足以排除普通指向动作，因此必须同时确认另外两指收拢；
- 进入后使用掌部中心而不是指尖位移，降低手指轻微弯曲造成的抖动。

## 几何判定

稳定几何层为四根手指分别计算伸展分数。每根手指同时使用 MCP 到指尖的直线度、指尖到手腕的归一化距离，以及指尖相对 PIP 的前伸量；坐标先按视频宽高比修正，并保留 MediaPipe 同帧纵深值。

滚动姿势分数定义为以下四项的最小值：

- 食指伸展分数；
- 中指伸展分数；
- `1 - 无名指伸展分数`；
- `1 - 小指伸展分数`。

分数达到 `0.80` 才允许成为新候选；已经锁定后使用 `0.55` 的退出阈值，避免临界抖动。进入还必须满足：

- 当前帧来自真实观测且通过关节点安全检查；
- 拇指与食指、中指、无名指的空间距离都达到捏合释放阈值；
- 上述指尖均有有限的同帧纵深数据；
- 当前不处于张掌、握拳、左键、右键或长按状态。

稳定指标额外输出掌部锚点，它是手腕和四个 MCP 关节的平均坐标，只用于滚动位移，不改变现有光标基准。

## 时间状态机

新增独立的纯 `ScrollGestureStateMachine`：

- 连续 5 个合格帧后从候选进入滚动；候选阶段不输出滚动量；
- 连续 3 个不合格帧后退出；短暂单帧抖动进入释放阶段但不产生滚动；
- 姿势在释放确认前恢复时，重新以当前掌部位置为基准，避免跳变；
- 丢手、预测帧、非法时间戳或安全门失败立即取消并清空残差；
- 每次重新进入都从零位移开始，第一帧绝不跳动。

引擎的全局锁扩展为 `left | right | scroll`。滚动锁定时左右捏合状态机只接收抑制证据；左右捏合或长按锁定时滚动状态机立即保持中立。张掌停止始终拥有最高优先级并清空全部动作。

## 滚动位移

滚动只读取相邻有效基准之间的掌部纵向位移，并除以当前掌部尺度，因此远近变化不会直接改变灵敏度。方向采用“手向上移动产生向上滚动、手向下移动产生向下滚动”的同向语义。

为避免抖动和低速丢失：

- 位移小于 `0.015` 个掌部尺度时不更新基准，慢速移动会自然累积；
- 超出死区后乘以 `28`，与上一帧小数残差合并；
- 只输出整数，单帧限制在 `-12…12`；
- 达到限幅时清空多余残差，避免停止移动后继续滚动；
- 反向移动可立即抵消残差。

## 输出、桌面与网页反馈

候选输出 `phase: candidate, candidate: scroll`；锁定输出 `state: scrolling, lockedGesture: scroll`；退出过程输出 `phase: releasing`。`scrollY` 只在锁定且姿势有效时为非零整数。

进入滚动候选后冻结网页和系统光标位置。桌面层用已有的 `candidate-scroll`、`scrolling`、`releasing-scroll` 蓝色圆形样式显示状态；非零 `scrollY` 调用已有的 `desktopBridge.scroll()`，不移动鼠标、不点击，也不关闭系统控制开关。

网页测试区显示累计滚动量并给出中文手势提示。诊断面板显示真实滚动姿势分数。README 更新当前功能和人工验收步骤；双击继续禁用。

## 轨迹与回归

现有 v5 轨迹已经包含 `scrollPoseScore`、`scroll` 事件和 `scroll` 手势类型，因此不升级格式。记录真实滚动分数，并在 `scrollY !== 0` 时写入滚动事件。

语义回归事件扩展为 `scroll`，固定矩阵新增：

- 合法双指姿势进入后向上和向下移动，必须产生有界、方向相反的滚动；
- 普通移动、左右捏合、长按、张掌、握拳、含糊多指、纵深分离都不得产生滚动；
- 单帧姿势闪现、候选期移动、姿势退出重进和丢手都不得产生跳变。

## 本阶段边界

- 不恢复双击；
- 不增加水平滚动、惯性滚动或速度设置；
- 不更改 MediaPipe 模型、不增加个人校准；
- 不更改 Electron IPC 的既有滚动范围和权限边界；
- 不把滚动姿势用于点击或拖动。
