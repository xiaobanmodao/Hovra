# Hovra 手势轨迹自动回归设计

## 目标

建立一套无需用户重复校准的自动回归系统。每次修改手势算法后，系统都使用固定的原始手部关节点轨迹重新运行真实 `GestureEngine`，自动发现漏点击、重复点击、误触、长按失败、释放失败和张掌停止退化。

## 选择的方案

采用“语义事件 + 有界时间窗”的混合判定。

不使用逐帧输出快照，因为滤波器或确认票数的合理调整可能让内部阶段移动一两帧，导致大量无意义失败。也不只使用召回率等聚合指标，因为聚合值无法可靠发现事件顺序错误和一次操作触发两次的问题。

每条回归用例包含：

- 严格校验的 `GestureTraceV5` 原始图像与世界关节点输入；
- 一个或多个期望事件时间窗；
- 每个时间窗允许的最少和最多事件次数；
- 默认启用的“时间窗外不允许任何动作事件”规则。

## 架构

### 回归评估器

新增独立的 `gestureRegression.ts`，负责：

1. 通过现有 `parseGestureTrace` 验证输入；
2. 按记录时间戳把每帧图像关节点、世界关节点和画面宽高比送入一个全新的真实 `GestureEngine`；
3. 把输出归一化成 `click`、`dragStart`、`dragEnd` 和 `pause` 语义事件；
4. 将事件与期望时间窗匹配；
5. 返回结构化报告，列出命中、缺失、重复、意外事件和事件延迟。

评估器不读取轨迹中旧版本保存的 `phase`、`lockedGesture` 或 `events` 作为当前真值。它们只保留为诊断信息，防止旧算法结果掩盖新算法退化。

### 固定回归用例

新增专用轨迹夹具构造器，以独立的原始关节点序列生成以下场景：

1. 短捏合：只允许一次左键点击，不允许长按事件；
2. 长按：只允许一次 `dragStart`，释放后只允许一次 `dragEnd`，不产生短点击；
3. 张开手掌：进入暂停状态，不产生点击或拖动；
4. 握拳：保持无操作，验证不会被误判为张掌或捏合；
5. 二维重合但纵深分离：不允许点击，覆盖用户曾遇到的侧向误触；
6. 普通移动：光标输入变化时不允许产生点击或拖动。

测试轨迹只包含合成关节点，不包含摄像头图片、视频、音频或个人信息。后续获得已确认标签的真实诊断轨迹时，可以按同一接口增加用例，不需要修改评估器。

## 判定规则

- 每个期望时间窗使用闭区间 `[startMs, endMs]`。
- 默认每个时间窗精确要求一次事件；可显式设置 `minCount` 和 `maxCount`。
- 同一个实际事件最多匹配一个期望时间窗。
- 未匹配的任何 `click`、`dragStart`、`dragEnd` 或 `pause` 都是意外事件。
- 同一连续暂停状态只产生一个 `pause` 语义事件。
- 报告必须稳定排序，使 CI 失败信息可重复。
- 空轨迹、非法时间窗、倒置时间窗、非整数次数和不可能的最小/最大次数必须在执行前拒绝。

## 集成

新增 `npm run test:gesture-regression`，只运行回归评估器和固定轨迹矩阵。现有 `npm test` 仍会自动发现这些测试，因此 GitHub Actions 无需新增工作流步骤即可在每次推送和拉取请求中执行。

本阶段不新增用户界面、不自动保存摄像头数据、不改变系统鼠标权限，也不恢复右键或滚动手势。

## 验收标准

- 评估器单元测试覆盖命中、缺失、重复、意外事件、暂停去重和非法配置。
- 六类固定场景全部通过真实引擎回放。
- 人为改变期望次数或窗口时，报告能明确指出具体用例、事件和时间范围。
- `npm run test:gesture-regression`、`npm test`、`npm run electron:typecheck` 与 `npm run build` 全部通过。
- 不引入新依赖，不扩大轨迹的隐私范围。
