# 手势识别引擎 V2 设计

## 背景与目标

当前识别引擎直接用单帧关键点、绝对归一化距离和最近指尖完成分类。摄像头距离、手掌旋转及关键点抖动会改变这些数值，导致动作不灵敏、临界状态反复切换、左键/右键/双击互相串扰以及滚动姿势不稳定。

V2 保留 MediaPipe Hand Landmarker 作为 21 点手部追踪器，重写其后的特征、滤波、候选确认和动作状态机。目标是稳定优先：允许约 60–100ms 的确认时间，优先实现低误触、跨距离一致和可复现调试。

## 成功标准

- 食指、中指、无名指捏合不会互相跳变或串键。
- 摄像头近、中、远三种距离使用同一套默认配置。
- 单帧抖动及连续 1–3 帧关键点异常不会触发点击或错误释放。
- 普通移动两分钟不产生误点击。
- 每种动作连续执行 20 次，至少成功识别 18 次，且不触发其他动作。
- 识别确认延迟的 95% 分位不超过 120ms。
- 系统控制始终只由用户显式开关控制。
- 最近识别过程可以导出为不包含图像的本地记录，并能在自动测试中确定性回放。

## 方案选择

采用规则引擎 V2，而不是直接依赖 MediaPipe 预置 Gesture Recognizer 或训练自定义模型。

MediaPipe 预置手势不覆盖左/右/双击所需的三种捏合关系，因此仍需自定义分类和状态控制。自定义训练模型需要大量个人样本、标注与评估，现阶段成本过高。规则引擎 V2 可以复用现有关键点模型，通过尺度归一化、时间确认和状态锁定解决已确认的根因，且行为可解释、可回放、可精确测试。

## 识别流水线

```text
MediaPipe 21点关键点
        ↓
手掌坐标与尺度归一化
        ↓
关键点自适应滤波
        ↓
连续手势特征与置信分数
        ↓
进入/退出双阈值
        ↓
时间确认与互斥动作锁定
        ↓
点击 / 拖动 / 右键 / 双击 / 滚动
```

每层使用明确接口并保持独立：

1. `HandGeometry` 从原始关键点构造手掌原点、方向基向量和尺度。
2. `LandmarkFilter` 对关键点做自适应时间滤波，不参与动作判断。
3. `GestureFeatures` 只输出连续数值，例如归一化捏合比例、手指伸展分数和手掌局部位移。
4. `GestureCandidateClassifier` 将连续特征转换为候选动作和置信分数。
5. `GestureStabilizer` 负责双阈值、连续时间确认、丢帧容错和中立冷却。
6. `GestureStateMachine` 负责互斥动作锁定以及离散点击、拖动、滚动事件。
7. `GestureTraceBuffer` 记录每帧输入摘要和各层输出，供导出与回放。

## 手掌坐标与尺度归一化

使用食指 MCP、无名指/小指 MCP、中指 MCP 和手腕构造稳定的手掌平面：

- 原点为掌心关键点的加权中心。
- 横轴沿食指 MCP 到小指 MCP 的方向。
- 纵轴为手腕到中指 MCP 的方向，并与横轴正交化。
- 尺度使用掌宽与手腕至中指 MCP 距离的稳健组合，防止单个关键点抖动造成比例跳变。

拇指到各指尖的距离除以手掌尺度，形成跨摄像头距离一致的捏合比例。滚动位移投影到手掌局部纵轴，不再直接使用画面 Y 坐标，因此手掌适度旋转和倾斜时仍可工作。

当尺度无效、关键点不足或基向量退化时，该帧标记为低质量，不生成新动作；状态稳定层决定是否短暂保持已有动作。

## 关键点滤波

实现无额外运行时依赖的自适应低通滤波：

- 静止和缓慢移动时加强平滑，压制关键点微抖。
- 快速移动时自动提高响应，避免光标明显拖尾。
- 使用真实帧时间差计算，不假设固定帧率。
- 手部重新出现、时间戳倒退或间隔过长时重置滤波器，避免旧位置污染新轨迹。

光标现有平滑继续保留，但手势判断只消费滤波后的手部关键点。这样光标体验和动作稳定性可以独立调节。

## 候选手势与双阈值

### 捏合

分别计算拇指至食指、中指、无名指的归一化比例。每种捏合使用两套阈值：

- 进入阈值较严格，距离必须足够小才成为候选。
- 退出阈值较宽松，只有距离明显增大才视为释放。

三个候选同时接近时，尚未锁定前可按分数选择最强候选；一旦确认，动作类型保持锁定，其他手指不能抢占，直到已锁定手指确认释放并完成中立冷却。

### 张掌

使用各手指关节角度、指尖相对掌心方向和伸展比例组合判断，不再只比较手腕到指尖的绝对距离。张掌只改变手势识别状态，不关闭系统控制。

### 滚动

滚动要求食指和中指伸展、无名指和小指弯曲，并同时满足关节角度与手掌局部方向条件。进入滚动时建立局部位移基准，首帧输出零；后续局部纵向位移经过死区、平滑、增益和单帧限幅后输出整数滚轮步长。

## 稳定状态机

默认采用时间确认而不是固定帧数，帧数只作为诊断显示：

- 候选进入：连续稳定约 80ms。
- 候选释放：连续稳定约 60ms。
- 滚动进入：连续稳定约 100ms。
- 动作结束后的中立冷却：约 120ms。
- 手部或关键点短暂异常容错：最长约 120ms。
- 左键捏合确认后保持 350ms 进入拖动，与现有用户习惯一致。

状态机的主要阶段为 `neutral`、`candidate`、`active`、`dragging`、`releasing`、`cooldown` 和 `lost`。候选动作只有在进入时间满足后才能变为 active。active 后锁定手势类型。释放时间满足后，左/右/双击产生对应离散事件；拖动只产生 `dragEnd`，不产生点击。

如果手部超过容错时间仍然丢失，拖动安全释放，其他候选或活动捏合直接取消，绝不把丢失解释为点击。应用切换、张掌、点击完成和短暂丢帧都不改变用户的系统控制总开关。

## 视觉反馈

圆形光标区分候选与确认状态：

- 候选阶段使用对应动作的淡色细环，并显示确认进度。
- 确认阶段使用现有实色动作状态。
- 释放确认期间保持动作色但降低亮度，避免视觉闪烁。
- 冷却阶段回到中性色。

诊断区域显示原始候选、已锁定动作、确认阶段、时间/帧进度、手掌尺度、三种捏合比例、滚动姿势分数和输入质量。原有绝对“Pinch threshold”改为用户可理解的“Gesture sensitivity”，内部同时调整标准化进入和退出阈值，且保持安全边界。

## 诊断记录与隐私

`GestureTraceBuffer` 使用内存环形缓冲区保留最近约 10 秒的数据。每帧记录：

- 相对时间戳和帧间隔。
- 21 个标准化关键点或无手标记。
- 手掌坐标、尺度和输入质量。
- 连续特征与候选分数。
- 稳定器阶段、确认进度、锁定动作和输出事件。
- 当前非敏感识别设置版本。

不保存视频帧、截图、音频、用户名、文件路径或其他个人数据。只有用户点击“Save diagnostic trace”时才通过受限 Electron IPC 打开本地保存对话框并写入 JSON。取消保存不产生文件；导出失败显示本地错误，不改变系统控制状态。

## 回放测试

回放器从 JSON 或测试夹具读取时间戳和关键点，逐帧送入与实际运行完全相同的滤波、特征、稳定器和状态机，不模拟最终结果。回放输出包括事件时间线、误触、漏识别、跨动作串键和确认延迟。

测试分三层：

1. 单元测试覆盖手掌坐标、尺度不变性、滤波器重置、双阈值和时间确认。
2. 状态机序列测试覆盖单帧抖动、候选切换、动作锁定、拖动、冷却、丢帧和安全释放。
3. 回放回归测试使用真实诊断记录，确保算法调整不会破坏已经稳定的动作。

每个缺陷必须先加入最小回放或合成序列并观察失败，再修改实现。真实记录进入仓库测试夹具前需再次确认其只含规定的非图像字段。

## 性能与错误处理

- 所有识别计算在单手 21 点上执行，避免新增神经网络和运行时依赖。
- 环形缓冲区容量固定，序列化只在用户主动保存时发生。
- 输入时间戳异常、尺度退化、非有限特征或未知设置版本会使该帧降级为低质量，不传播非有限值。
- 模型推理失败沿用现有摄像头错误处理；识别引擎重置并安全释放拖动。
- 覆盖层或诊断 UI 更新失败不得阻塞系统鼠标动作。
- MediaPipe 检测、存在和追踪置信度先保持默认值，待回放证据证明模型层存在问题后再单独调整，避免将分类器缺陷误归因于模型。

## 实施顺序

1. 建立 trace 数据结构、内存缓冲与确定性回放测试架构。
2. 实现手掌几何和标准化特征，并用尺度/旋转序列验证。
3. 实现自适应关键点滤波。
4. 实现候选分数、双阈值和时间稳定器。
5. 替换现有手势状态机并保持桌面动作接口兼容。
6. 接入候选视觉、诊断面板、灵敏度设置和安全导出。
7. 用合成序列和实际摄像头记录完成量化验收。
