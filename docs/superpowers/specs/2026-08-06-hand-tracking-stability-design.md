# 关节追踪稳定层设计

## 目标

在不改变摄像头覆盖层原始坐标的前提下，为手势控制建立一套独立、低延迟且能够拒绝异常关节点的追踪稳定层。它需要减少静止抖动、阻止单点瞬移制造点击或张掌，并在极短跟踪空洞中保持光标连续；任何预测数据都不得触发点击、释放确认或张掌停止。

本阶段不新增手势，不改变用户当前的短捏合单击、持续捏合长按和张掌停止语义。

## 当前证据与根因

- `GestureEngine` 当前把 MediaPipe 的 21 个原始点直接交给 `measureStableHand()`，关节抖动和单点跳变会直接进入捏合、握拳和张掌几何。
- 项目已经存在 `AdaptiveLandmarkFilter`，但它只在自己的单元测试中使用，没有接入任何实时控制路径。
- 现有自适应滤波只能平滑每个点，无法区分“整只手真实移动”和“单个关节异常瞬移”。异常点进入低通后还可能被缓慢拖过点击阈值。
- MediaPipe Hand Landmarker 的结果包含手部坐标和 handedness，但没有可直接用于安全门的逐关节置信度。当前 `normalizeLandmarks()` 也只保留 `x/y/z`。因此“置信度门控”必须由时间一致性、掌部整体运动和骨段一致性共同推导，不能伪造模型没有提供的分数。
- 摄像头覆盖层现已严格使用原始图像坐标。控制稳定器不得把处理后的坐标传回 `CameraStage`。

## 方案比较

### 方案 A：掌部运动补偿 + 单点异常拒绝 + 低延迟自适应滤波（采用）

先用手腕和四个掌指关节估计整只手的共同位移，再比较每个关节相对该位移的残差与相邻骨段变化。共同移动被视为真实动作；仅少数点发生的大残差被视为异常。接受后的帧再进入 One Euro 风格的自适应滤波。

优点是能够同时保持快速跟手和拒绝单点跳变，不需要第二个推理模型；缺点是需要明确处理首帧、恢复、全局快速移动和真实手指弯曲的边界。

### 方案 B：直接接入现有 `AdaptiveLandmarkFilter`

实现最少，也能减少静止抖动，但无法识别异常点。一个错误的拇指尖或食指尖会被平滑成一条持续多帧的错误轨迹，可能比原始单帧错误更容易越过点击迟滞，因此不采用。

### 方案 C：恢复 MediaPipe + Apple Vision 双模型

可以用模型一致性过滤结果，但此前已经出现模型延迟和灵敏度冲突；它还增加图像编码、异步时序和平台绑定。本阶段优先修复单模型时间一致性，不重新引入双模型。

## 架构边界

新增纯 TypeScript 组件 `HandTrackingStabilizer`，放在 `src/gesture/handTrackingStabilizer.ts`。它不访问摄像头、DOM、Electron 或 React，只消费每帧原始坐标和单调时间戳。

```ts
export type StabilizedHandFrame = {
  controlLandmarks: Landmark[] | null;
  source: "observed" | "predicted" | "lost";
  gestureSafe: boolean;
  quality: number;
  rejectedIndices: number[];
};

export class HandTrackingStabilizer {
  update(landmarks: Landmark[] | null, nowMs: number): StabilizedHandFrame;
  reset(): void;
}
```

数据职责保持严格分离：

- `App` 保存并传给 `CameraStage` 的仍是 MediaPipe 原始 `landmarks` 和 `worldLandmarks`。
- `GestureEngine` 内部拥有一个 `HandTrackingStabilizer`，只使用 `controlLandmarks` 计算光标和手势。
- 诊断记录继续保存原始坐标，以便后续自动回放重新执行相同稳定算法，而不是保存已经处理过的结果。
- 世界坐标不参与本阶段的二维稳定和关节重定位；当前点击使用的图像归一化 `z` 与 `x/y` 一起经过同帧异常判断和低延迟滤波。

## 稳定算法

### 1. 输入验证与初始化

输入必须恰好包含 21 个有限坐标，时间戳必须有限且严格递增。首个有效帧原样复制为控制基线，不进行历史推断。时间戳倒退、帧间隔超过 250ms 或显式 `reset()` 会清空全部历史。

### 2. 掌部共同运动

使用索引 `[0, 5, 9, 13, 17]` 作为掌部锚点。分别计算它们相对上一接受帧的 `x/y/z` 位移，并对每个轴取中位数，得到 `palmDelta`。中位数能够容忍一个或两个锚点异常，同时允许整只手快速平移。

如果输入没有 `z`，稳定器只处理 `x/y` 并在输出中继续省略 `z`，不得用 `0` 伪造纵深；现有点击安全门会继续把缺少纵深的数据视为不可点击。

当前掌宽使用食指掌指关节 `5` 到小指掌指关节 `17` 的距离。上一帧和当前帧掌宽都必须大于 `1e-6`。掌宽单帧变化超过上一稳定值的 55% 时，该帧标记为不安全，但仍可用预测点维持光标。

### 3. 单点异常判断

每个点的期望位置为“上一稳定点 + `palmDelta`”。计算当前观测到期望位置的三维残差，并用上一稳定掌宽归一化。

满足以下任一组合时拒绝该点：

- 归一化残差大于 `0.42`，并且该点至少一条相邻骨段长度相对上一稳定帧超出 `[0.45, 2.2]`；
- 归一化残差大于 `0.8`，无论骨段长度如何；
- 坐标越出宽松有效范围 `x/y ∈ [-0.25, 1.25]` 或 `z ∈ [-1.5, 1.5]`。

掌部锚点先用共同位移一致性判断；如果三个及以上锚点都呈现方向和幅度一致的变化，则将其视为真实整手运动，不按绝对速度拒绝。这样快速移动不会被误当成五个同时出错的点。

被拒绝的点使用期望位置代替，并记录其索引。该替代只用于控制连续性，本帧 `gestureSafe` 必须为 `false`，所以替代点不能触发任何手势状态变化。

### 4. 自适应滤波

完成异常替代后使用现有 One Euro 思路进行低延迟滤波：

- 拇指和食指链 `[1,2,3,4,5,6,7,8]` 使用 `minCutoff = 1.35`、`beta = 20`，优先降低点击延迟。
- 其余点使用 `minCutoff = 1.0`、`beta = 16`，优先稳定掌部、张掌和握拳几何。
- 两组共享真实帧间隔，不能假设固定帧率。
- 组间最终仍按原始 21 点索引合并，不改变手部拓扑。

### 5. 短时丢点

有效观测短暂缺失且距离上一有效帧不超过 80ms 时，返回 `source: "predicted"`。每个点按最近一次接受速度外推，单帧外推位移限制为上一掌宽的 `0.35`，避免速度估计爆炸。

预测帧必须满足：

- `gestureSafe: false`；
- 可继续提供控制光标位置；
- `GestureEngine` 向点击状态机发送跟踪中断，从而立即释放已按下鼠标并清除候选；
- 不计算或累积捏合、释放、张掌、握拳确认帧。

缺失超过 80ms 后返回 `source: "lost"` 和 `controlLandmarks: null`，界面进入未检测到手部状态。观测恢复后，点击状态机仍要求先看到完整分离基线才能重新布防。

## GestureEngine 数据流

`GestureEngine.update(rawLandmarks, nowMs, ...)` 首先调用稳定器：

1. `source === "observed" && gestureSafe`：用稳定点完成全部几何和手势计算。
2. `source === "observed" && !gestureSafe`：用稳定点更新光标，但点击状态机按跟踪中断处理，张掌/握拳计数清零。
3. `source === "predicted"`：只输出预测光标和低质量诊断；点击状态机按跟踪中断处理。
4. `source === "lost"`：保持当前丢手流程。

为避免把预测帧误显示为可靠追踪，`GestureDiagnosticsSnapshot` 新增：

- `trackingSource: "observed" | "predicted" | "lost"`；
- `trackingQuality: number`；
- `rejectedLandmarkCount: number`。

质量分定义为：完整安全观测为 `1`；每拒绝一个点扣 `0.12`，最低为 `0.2`；预测帧固定为 `0.15`；丢失为 `0`。质量分只用于诊断和安全门，不修改摄像头覆盖层透明度或位置。

## 错误和安全处理

- 非法帧、非有限坐标和时间戳异常不得抛出到渲染循环。
- 任何异常替代或预测帧都不得产生 `click`、`dragStart`、张掌暂停或释放确认点击。
- 如果异常帧发生在长按期间，必须产生一次 `dragEnd`，随后预测光标可继续移动，但鼠标保持抬起。
- 稳定器不会保存图像、设备信息或无限历史；仅保存上一接受帧、上一输出帧、速度、掌宽和滤波状态。
- 原始覆盖层路径不读取稳定器输出，确保用户看到的点仍是模型实际返回的位置。

## 验证标准

- 21 点静止交替噪声经过稳定器后，稳定区间范围小于原始范围的 60%。
- 整只手在 100ms 内快速一致平移时，控制点至少跟随真实位移的 80%，且不被标记为单点异常。
- 单帧拇指尖或食指尖瞬移到另一指尖时，本帧 `gestureSafe` 为假，不能制造捏合接触、释放或点击。
- 任意一条骨段单帧伸长超过允许范围时拒绝对应异常端点，不移动摄像头覆盖层原始点。
- 最长 80ms 丢点可以输出预测光标，但不能产生任何手势事件；超过 80ms 必须进入 `lost`。
- 长按期间异常或丢点会产生一次安全抬起，后续帧不重复。
- 恢复观测后必须先完整分离才能重新点击。
- 单元测试覆盖稳定器算法、引擎安全集成、诊断字段、原始显示坐标隔离和真实时间间隔。
- 最终通过完整 Vitest、Electron TypeScript 检查、生产构建和桌面运行验证。

## 非目标

- 不重新引入 Apple Vision 或第二个手部模型。
- 不使用固定骨长重绘或移动摄像头覆盖层。
- 不让预测坐标触发手势。
- 不在本阶段恢复右键、滚动或其他高级操作。
