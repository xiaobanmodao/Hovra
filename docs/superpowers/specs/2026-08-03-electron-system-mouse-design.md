# Electron 系统鼠标控制：设计规格

## 目标

将现有手势网页演示封装为 macOS Electron 应用，在用户授予辅助功能权限并主动启用控制后，使用现有的手势状态机移动、点击与拖拽真实系统鼠标。

## 范围

- Electron 渲染进程复用现有 React、MediaPipe、校准面板与手势状态机。
- 预加载桥接只暴露 `move`、`click`、`mouseDown`、`mouseUp` 与只读权限状态。
- 主进程检查 macOS 辅助功能权限并执行系统鼠标事件。
- UI 显示权限状态和系统控制开关；默认暂停，只有权限已授予且用户主动开启后才控制系统鼠标。
- 张开手掌、丢失手部、摄像头停帧、关闭开关、窗口失焦和应用退出均会先释放鼠标按钮，再暂停控制。

## 不在范围内

- Windows、Linux 或移动端鼠标控制。
- 全局快捷键、窗口切换、滚动、键盘模拟或后台常驻。
- 向网络上传视频、关键点或权限数据。

## 架构

渲染进程只决定何时发送抽象鼠标动作；它不能直接调用 Node 或系统 API。`preload` 使用 `contextBridge` 暴露最小白名单。主进程为每个动作检查当前启用状态和已授权的辅助功能权限，再通过 macOS 鼠标控制适配器执行。适配器维护是否已按下鼠标的状态，以便所有安全路径都可以幂等地释放。

## 安全与交互规则

- 系统控制开关默认关闭；权限未授予时显示说明和前往系统设置的入口。
- 只有 `tracking`、`pinching` 与 `dragging` 状态、且开关开启时，食指位置才映射到主屏幕坐标并发送移动。
- 短捏合发送一次 `click`；长捏合开始发送 `mouseDown`，结束时发送 `mouseUp`。
- 任意安全条件优先发送 `mouseUp`，并将开关设为暂停；重复释放不会产生额外副作用。
- 应用启动后需用户重新主动开启控制；控制状态不持久化。

## 测试与验收

- 预加载 API 不暴露 Node、文件系统或任意 IPC 调用。
- 权限拒绝时无法启用，且不会发送鼠标事件。
- 正常路径验证移动、短捏合单击、长捏合按下/释放。
- 每一种安全条件均验证按下状态被释放并暂停。
- 在 macOS 测试机授予辅助功能权限后，真实验证移动、点击、拖拽以及张开手掌紧急暂停。
