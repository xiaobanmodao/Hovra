# 手势控制网页演示：设计规格

## 目标

交付一个无需后端的浏览器网页演示。用户授权摄像头后，可通过单手手势在网页内移动虚拟光标、点击目标和拖拽目标。识别完全在本机浏览器执行。该项目为后续桌面鼠标控制版本提供可复用的手势识别与状态机模块。

## 范围

### 网页第一阶段

- 显示镜像摄像头预览、手部骨架、虚拟光标和当前状态。
- 食指指尖控制虚拟光标位置。
- 拇指与食指捏合触发单击。
- 持续捏合触发并保持网页内的拖拽操作；松开时结束拖拽。
- 张开手掌暂停手势控制。
- 提供可点击、可拖动的网页演示对象，以验证手势映射。
- 摄像头拒绝、不可用、识别不到手时提供明确状态反馈。

### 不在本阶段范围内

- 控制操作系统真实鼠标。
- 后端、账号、数据上传或云端推理。
- 多手协作、手势自定义、移动端专项适配。

## 技术选型

使用 MediaPipe Tasks Vision 的 Hand Landmarker Web 版本。模型在浏览器本地运行，输出 21 个手部关键点。应用作为静态单页网页实现；不要求服务器端 API。

## 架构

### Camera

负责请求 `getUserMedia` 摄像头权限、将视频镜像显示在预览区，并提供每帧视频图像给识别模块。

### Hand Tracker

封装 MediaPipe 初始化和逐帧识别。只选择第一只稳定检测的手，输出标准化关键点、检测置信度和时间戳。模型或摄像头不可用时向 UI 报告可理解的错误状态。

### Gesture Engine

将关键点转换为手势事件。

- `move`：食指指尖坐标。
- `pinch-start`：拇指尖与食指尖距离从阈值外进入阈值内。
- `pinch-hold`：连续保持捏合。
- `pinch-end`：距离离开阈值。
- `paused`：五指张开时启用；该状态禁止移动、点击和拖拽。
- `lost`：连续若干帧未检测到手时启用；行为与暂停一致。

状态机将避免重复点击：短暂捏合映射为一次点击，达到拖拽保持时间后开始拖拽，松开时结束。阈值与时间均应集中为可调常量。

### Cursor Controller

将镜像视频中食指位置映射到网页视口坐标。对位置应用指数平滑，限制在视口边界内，并根据状态机将事件派发给演示目标。它只控制网页内虚拟光标，不访问系统鼠标 API。

### UI

由视频画布、关键点绘制层、虚拟光标、状态面板和交互测试区组成。状态面板至少展示摄像头状态、识别状态和当前手势状态。测试区包含可点击卡片与可拖动对象，能直观看到点击计数与拖拽结果。

## 数据流

`摄像头视频帧 → Hand Tracker → Gesture Engine → Cursor Controller → UI 演示目标`

视频帧和关键点仅保留在浏览器内存中，刷新页面后不持久化。

## 错误处理

- 摄像头权限拒绝：显示授权说明与重新尝试入口。
- 无可用摄像头：显示设备不可用提示。
- 模型加载失败：显示加载失败状态与刷新建议。
- 手部短暂丢失：保持当前虚拟光标位置并暂停交互；若正在拖拽则安全结束拖拽。
- 浏览器不支持必要 API：展示兼容性提示。

## 验收标准

1. 在支持摄像头的桌面 Chrome 或 Edge 中，用户可以授权并看到镜像预览与关键点。
2. 食指移动会平滑驱动虚拟光标，不超出网页视口。
3. 短捏合只产生一次点击；长捏合能够拖拽演示对象并在松开时结束。
4. 张开手掌和手部丢失会暂停交互，且不会意外触发点击或拖拽。
5. 拒绝权限、模型加载失败和无手部检测均有可理解的 UI 反馈。

## 后续桌面阶段

保留 Hand Tracker 和 Gesture Engine 的接口。将 Cursor Controller 替换为桌面适配器（Electron 主进程或 Python 桌面服务），由获得系统辅助功能权限的适配器驱动真实鼠标。网页演示的阈值、平滑和状态机逻辑保持复用。
