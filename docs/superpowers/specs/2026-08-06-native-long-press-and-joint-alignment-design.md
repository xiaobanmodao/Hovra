# 原生长按与关节点精确对齐设计

## 目标

让同一个拇指—食指捏合动作同时支持短按和原生长按，并修复摄像头覆盖层关节点被二次几何约束移离模型原始位置的问题。系统仍只保留移动、左键和张掌停止；长按是左键的持续按下形态，不新增容易混淆的手势。

## 已确认根因

- 点击状态机把超过 `maxGestureMs` 的稳定捏合当作超时并取消，输出中没有鼠标按下和抬起事件。
- `GestureEngine` 固定输出 `dragStart: false`、`dragEnd: false`，`App` 也从未根据手势调用桌面桥接的 `mouseDown()`。
- `handOverlayModel` 会按固定骨长比例重算每个手指关节的二维坐标。它改变了 MediaPipe 返回的坐标，因此覆盖层关节点与视频中的手部产生可见偏移。

## 长按交互

1. 首个稳定分离帧只建立安全基线。
2. 拇指与食指连续接触两帧后进入已捏合状态，并锁定捏合前的光标位置。
3. 在 420ms 之前连续两帧释放，发送一次普通左键点击，位置使用锁定点。
4. 接触持续达到 420ms 时只发送一次按下事件：先把系统光标移动到锁定点，再调用 `mouseDown()`。
5. 长按已经开始后，光标继续跟随食指移动，系统按钮保持按下，因此既能产生原生长按，也能自然进行选择和拖动。
6. 长按后的连续两帧释放只发送 `mouseUp()`，不得再发送单击。
7. 手部丢失、时间戳异常、张掌停止、握拳抑制、关闭系统控制、窗口安全暂停和组件卸载都必须释放鼠标，避免系统按钮卡住。

长按开始前继续使用速度和移动半径防误触门。长按开始后不再使用移动半径取消，因为用户可能在保持按下时有意移动；跟踪丢失和抑制仍然具有最高优先级。

## 事件契约

`PinchClickOutput` 新增：

- `holdStarted`：本帧刚达到长按阈值，只能出现一次。
- `holdEnded`：已开始长按后，本帧确认释放或因安全原因中断，只能出现一次。
- `holdCursor`：长按开始时使用的捏合前锁定坐标。
- `holding`：当前是否处于系统按钮应保持按下的阶段。

`GestureEngine` 将这些事件映射到已有的 `GestureOutput.dragStart`、`dragEnd` 和 `dragging` 状态，避免扩大桌面桥接协议。对用户显示的中文状态改为“长按中”，但事件仍可实现移动中的系统拖动。

## 关节点对齐

- 覆盖层的 21 个二维点逐点复制 MediaPipe 图像坐标，不再修改 `x` 和 `y`。
- 掌面、骨段端点、关节圆和捏合连接带全部引用同一组原始二维点。
- 世界坐标或图像 `z` 只用于深度排序和透明度，不影响二维位置。
- 掌宽仍用于绘制半径和骨段粗细。
- 固定骨长约束从绘制路径删除；异常骨长今后只能作为质量提示，不能伪造关节位置。

## 验证标准

- 短捏合仍只产生一次点击。
- 420ms 边界只产生一次按下，释放只产生一次抬起且没有额外点击。
- 长按中可继续派发光标移动。
- 丢手、张掌和关闭控制均会安全抬起。
- 21 个覆盖点的 `x/y` 与输入图像坐标逐点严格一致，包括异常长骨段输入。
- 完整 Vitest、Electron TypeScript 检查和生产构建全部通过，并重新启动桌面新版。
