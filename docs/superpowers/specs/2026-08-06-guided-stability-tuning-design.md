# 引导式稳定性测试与自动调优设计

## 目标

在约 4 分钟内完成一轮有真实动作标签的个人稳定性测试，量化捏合点击的召回率、误触、重复点击、响应延迟和运行性能，并给出可解释、可撤销的保守调优建议。

本阶段不增加手势种类、不更换手部模型，也不保存摄像头画面。测试期间必须暂停系统鼠标控制，只记录本地骨骼点、派生距离、识别事件和测试标签。

## 方案选择

采用“引导动作 + 已知时间窗 + 用户纠错”的标注方式。程序先提示用户做指定动作，因此知道当前窗口应是接触、分离还是负样本；用户只需要在漏识别或误识别时纠正。相比被动日志，这能提供真实标签；相比训练个人模型，它需要的数据少、风险低，并能直接作用于当前稳定内核。

## 测试流程

测试由一个独立面板管理，进入测试时立即调用现有暂停接口，并在测试结束后保持系统控制关闭，是否重新开启仍由用户决定。

1. **准备检查（约 20 秒）**
   - 摄像头和识别器必须可用。
   - 连续检测到完整单手，掌部尺度、深度和帧率达到采样要求后才允许开始。
   - 实时显示“手掌未完整进入画面”“纵深数据不稳定”“帧率不足”等中文提示。
2. **20 次正样本（约 2 分钟）**
   - 依次覆盖正面、左侧向、右侧向、近距离和远距离，每类 4 次。
   - 每次包含“张开拇指与食指”“捏合并短暂停留”“再次分开”三个节拍。
   - 程序以提示时间窗标记 `separate`、`contact`，过渡帧标记 `ignore`。
   - 若接触窗内没有点击，记录漏识别；同一接触窗产生多个点击，记录重复点击。
3. **负样本（约 1 分钟）**
   - 依次执行手指在画面中重合但不接触、握拳、张开手掌、快速移动四类动作。
   - 所有有效帧标记为 `separate`；任何点击均记为误触。
4. **结果页**
   - 显示完成度、有效样本数、召回率、误触数、重复点击数、P95 响应延迟、有效帧率和推理 P95。
   - 按动作方向列出薄弱项，明确区分“识别失败”和“样本质量不足”。

## 数据与状态模型

新增测试会话结构，保存测试步骤、提示窗口、每帧标签、现有 `GestureTraceFrame` 的必要字段和用户纠错。会话最大约 5 分钟，采用有界数组，防止长期占用内存。

测试状态为：`idle` → `readiness` → `positive` → `negative` → `analyzing` → `complete`，并支持 `cancelled`。切换步骤只由纯状态机完成，React 组件只负责呈现和转发当前帧，便于用虚拟时钟完整测试。

本地保存结果时只写 JSON 数值和骨骼点，不写视频帧、截图、姓名或设备标识。

## 自动判定

基础指标复用并扩展现有 `benchmarkPinchTrace`：

- 召回率 = 有且仅有一次点击的正样本数 / 有效正样本数。
- 误触 = 负样本窗口内的点击总数。
- 重复点击 = 正样本窗口中第一次之后的点击数。
- 响应延迟 = 接触提示窗口开始到首次识别锁定的时间，报告 P95。
- 性能 = 有效 FPS 和推理耗时 P95。
- 样本质量 = 手部存在、21 个点完整、深度可靠、掌部尺度处于有效范围、帧间时间合理。

默认通过条件：20 个有效正样本中召回率不低于 90%，负样本误触为 0，重复点击为 0，P95 响应延迟不高于 150 毫秒，有效帧率不低于 24。该短测用于个人调优，不替代后续 200 次和 30 分钟压力验收。

## 调优算法

当前稳定内核的点击边界是固定配置，因此第一版调优只推荐可安全映射到当前引擎的参数，不制造“已优化”的假象。

1. 从每个有效接触窗提取空间捏合比例的稳定低分位值，从分离及负样本提取稳定低分位值。
2. 只有接触分布与负样本分布之间存在足够间隔时才生成建议；阈值放在两者之间并保留安全边距。
3. 建议值限定在经过测试的安全范围内，释放阈值始终高于接触阈值，保持迟滞。
4. 若分布重叠、某方向样本不足或建议会提高负样本误触风险，结果为“暂不建议调整”，并说明需要补测的动作。
5. 应用前展示当前值、建议值和离线重放得到的预期指标。应用后可一键恢复测试前配置。

为支持真正的个性化边界，`GestureSettings` 将新增可选的接触和释放比例。未设置时继续使用当前稳定默认值，确保旧配置和现有行为不变。

## 界面

在“手势诊断”附近增加“开始稳定性测试”入口。测试面板使用大号中文动作标题、倒计时、进度 `当前/总数`、实时质量状态和简明的人手动作图。已有校准图可以复用，但必须明确展示拇指与食指，侧向步骤需分别展示方向。

测试进行中禁用参数滑块和系统控制按钮。取消测试、关闭页面或摄像头失效时立即结束采集并保持系统控制暂停。

结果页提供：

- “应用推荐设置”：只在建议安全且离线重放未增加误触时可用。
- “保持当前设置”：不修改任何值。
- “恢复测试前设置”：应用建议后可用。
- “保存测试报告”：仅桌面版显示，复用安全的本地保存桥接。

## 错误与边界处理

- 检测不到手或质量不足时暂停当前动作计时，不把坏帧算作失败。
- 摄像头停滞、识别器异常或页面失焦时暂停测试并显示恢复提示。
- 连续三次无法获得有效样本时允许跳过该方向，但最终标为数据不足且禁止自动应用。
- 所有百分位和阈值计算处理空数组、非有限值和时间戳重复；任何无效输入都返回不可调优结果。
- 测试启动、取消、完成及应用设置均不得自动重新启用系统鼠标。

## 验证

- 纯逻辑单元测试覆盖状态转换、标签窗口、暂停坏帧、指标、百分位、阈值建议、安全拒绝和撤销。
- React 测试覆盖完整中文流程、实时提示、系统控制暂停、应用与恢复按钮状态。
- App 集成测试证明测试期间不会下发桌面移动或点击，结束后系统控制仍关闭。
- 使用固定手势序列重放正面、侧向、投影重合、握拳和张掌样本，验证结果可重复。
- 最终运行全部 Vitest、Electron 类型检查和生产构建；桌面打包后再做一次启动冒烟检查。

## 非目标

- 不增加右键、拖动、滚动或其他手势。
- 不上传数据、不训练云端或本地神经网络。
- 不让程序在没有真实标签的情况下自动修改阈值。
- 不自动开启系统控制。
