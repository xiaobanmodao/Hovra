# 意图感知手势控制与 2.5D 手部反馈设计

## 目标

用可解释的状态机和真实使用反馈，替换无法判断用户意图的图片动作测试。系统继续只支持移动、左键点击和张掌停止，但点击必须满足稳定捏合、稳定释放、低速、非抑制手势和位置锁定等条件；用户可在正常使用中把最近一次点击标记为“误触”或“正确点击”，应用只用这些真实标签评估并给出保守建议。

同时把摄像头上的简单二维骨骼线改为受约束的 2.5D 手部覆盖层，让掌心、指节、拇指与食指、前后遮挡和捏合位置更容易理解。覆盖层只用于反馈，不参与原始模型推理，因此不会因为绘制误差反向影响点击判断。

## 交互范围

- 保留：食指引导的光标移动、拇指与食指捏合左键点击、张开手掌停止。
- 暂不恢复：右键、滚动、缩放、多指快捷操作和拖动。
- 旧的四分钟图片测试退出主界面，不再把脚本时间窗当成用户真实意图。
- 不保存摄像头画面。反馈记录只包含时间、归一化骨骼派生值、状态机事件、光标速度、点击位置和用户标签。
- 系统控制是否开启始终由用户决定；记录反馈、应用建议和页面重载均不得自动开启。

## 点击状态机

点击状态为 `tracking`、`pinch-candidate`、`pinched`、`release-candidate` 和 `suppressed`。

1. 正常跟踪时持续更新滤波光标，并保存“最后一个未捏合位置”。
2. 捏合概率连续越过进入边界至少两个有效帧且达到最短进入时间后，进入 `pinched`，同时锁定捏合前光标位置。
3. 捏合期间不发送系统点击。只有连续两帧越过释放边界，且整个动作满足时长与移动半径限制，才在锁定位置发送一次点击。
4. 单帧距离突变、模型丢帧、高速移动、持续时间过长、轨迹移动过大、张掌、握拳或质量不足都取消当前候选，不产生点击。
5. 张掌、握拳或跟踪中断后进入抑制状态；只有连续获得干净的非捏合帧并经过冷却时间后才可重新布防。

进入和释放使用不同边界形成迟滞；事件还需要时间迟滞和至少两帧确认。点击位置采用捏合前锁定点，避免手指闭合本身推动光标。

## 光标滤波与速度门控

光标使用 One Euro 自适应低通：慢速时增强稳定性，快速移动时降低延迟。过滤器用真实帧间隔计算导数，遇到长时间断帧重置，避免恢复后瞬移。

状态机同时计算归一化光标速度。速度高于点击上限时不允许进入捏合；已进入候选后速度越界则立即取消。点击释放时再次检查整个手势的峰值速度和锁定点到当前位置的距离，防止移动途中误触。

## 真实意图反馈

每次系统产生点击时创建一个短时反馈事件，并保存点击前后的有限帧轨迹。事件初始为“未标注”，不会被默认当成正确点击。主界面显示最近事件并提供两个明确按钮：

- `这是误触`：用户没有点击意图。
- `这是正确点击`：用户确认这次操作符合意图。

事件超过反馈窗口仍未选择时记为“未标注”，不能用于自动调参。数据存入浏览器本地存储，有数量上限，可一键清空；不包含图片、视频和设备标识。

## 离线比较与建议

只有同时拥有足够的正确点击与误触标签时才生成建议。分析器在固定候选参数集合上重放已标注轨迹，以以下优先级选取参数：

1. 不增加误触；
2. 尽量保留正确点击；
3. 在前两项相同的情况下减少识别延迟。

建议必须经过边界验证：进入阈值小于释放阈值、时间和速度在安全范围内、误触数严格下降且正确点击保留率不低于安全下限。否则只显示数据统计和继续收集提示，不提供可应用设置。应用前保留设置快照，可撤销；应用与撤销均不改变系统控制开关。

## 2.5D 手部覆盖层

覆盖层以手腕和四个掌指关节建立局部坐标系，以掌宽归一化尺寸，并按 MediaPipe 的 `z` 或世界坐标深度排序绘制：

- 掌心使用腕部、食指/中指/无名指/小指掌指关节构成的半透明多边形。
- 骨段使用圆角胶囊而不是细直线，宽度从掌端到指尖逐级变细。
- 关节按层级显示圆形节点；拇指尖和食指尖使用不同的高亮色。
- 深度靠前的骨段后绘制并提高不透明度，远端降低不透明度，表现前后关系。
- 捏合候选时在拇指尖与食指尖之间显示连接带；可点击、被速度阻止和被张掌抑制使用不同颜色与中文状态。
- 输入点不完整或深度可靠性不足时降低覆盖层置信表现，而不是伪造精确姿态。

骨长仅用于绘制约束：以当前掌宽和手指比例限制异常伸缩，并对端点做轻量时间平滑。点击算法继续使用原始归一化几何与概率融合数据，保持职责分离。

## UI 集成

主界面用“真实使用反馈”替换“稳定性测试”主入口。面板始终显示已标注正确数、误触数、未标注数、当前建议状态和清除入口。刚发生点击时短暂突出反馈卡，但不弹窗、不阻塞操作。

摄像头区域显示 2.5D 覆盖层、当前点击状态与阻止原因。所有用户可见文本使用中文。旧测试逻辑和资源可以暂留代码库用于兼容历史报告，但不参与默认流程。

## 边界与错误处理

- 时间戳倒退、非有限坐标、少于 21 个点、掌宽过小或帧间隔过长时重置候选。
- 跟踪恢复后的首帧只建立基线，不可触发点击。
- 同一手势最多生成一次点击；必须完整释放并通过冷却后才能再次布防。
- 本地存储损坏时忽略坏数据并恢复空记录，不影响摄像头和系统控制。
- 回放结果不确定、样本不足或分类不可分时拒绝建议。
- 所有数组均有固定上限，避免长时间运行造成内存增长。

## 验证标准

- 单元测试覆盖两帧迟滞、释放触发、单次点击、锁定位置、高速取消、张掌/握拳抑制、断帧恢复和超时取消。
- 单元测试覆盖反馈事件的未标注语义、标注更新、容量限制、损坏持久化恢复与保守建议拒绝。
- 单元测试覆盖 2.5D 掌心拓扑、21 关节、20 骨段、深度排序、骨宽和不完整输入降级。
- React 测试覆盖中文反馈面板、最近点击标注、应用/撤销不改变系统开关以及旧图片测试不再出现在主流程。
- 最终必须通过完整 Vitest、Electron TypeScript 检查、生产构建和浏览器页面冒烟验证。
