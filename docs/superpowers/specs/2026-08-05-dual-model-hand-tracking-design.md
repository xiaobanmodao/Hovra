# MediaPipe 与 Apple Vision 双模型手部识别设计

日期：2026-08-05

## 目标

解决单一 MediaPipe Hand Landmarker 在侧向、自遮挡捏合时稳定输出错误指尖位置的问题。桌面版使用两个独立模型判断拇指和食指接触；网页继续使用 MediaPipe 降级路径。移动、左键点击、张手停止仍是唯一手势功能。

## 已确认根因

当前 `@mediapipe/tasks-vision` 已是 npm 最新稳定版 `1.0.1`，项目使用的也是官方 Hand Landmarker float16 v1 模型。上一轮已经修正二维、三维坐标混用，但用户现场仍看到骨骼关键点与真实指尖相距很远，说明错误发生在模型关键点输出层。单目模型在侧掌自遮挡下可能稳定地猜错被遮挡指尖，继续修改距离公式不能修复错误输入。

## 架构

### 主模型：MediaPipe GPU

- 保留 MediaPipe 负责手掌定位、光标移动和张手停止。
- `baseOptions.delegate` 设置为 `GPU`，失败时自动重建 CPU 实例。
- 保持单手和视频模式，不降低摄像头采样频率。

### 验证模型：Apple Vision

- 新增常驻 Swift 命令行助手，使用 `VNDetectHumanHandPoseRequest`。
- 渲染器以最多每 80 毫秒一次的频率，将保持宽高比、最长边 512 像素的 JPEG 帧通过固定 IPC 接口送到主进程。
- 主进程以逐行 JSON 协议把帧送给常驻助手，助手返回 21 个二维关键点及逐点置信度。
- Vision 坐标的左下角原点转换为网页使用的左上角原点；不做镜像，保持与 MediaPipe 原始视频坐标一致。
- 每次最多一个请求在途。新帧不会排队，避免推理延迟累积。

### 融合识别

- 新增 `SecondaryHandObservation`，包含关键点、置信度、采集时间和推理耗时。
- Apple Vision 观测超过 180 毫秒、关键点不足 21 个或关键点置信度低于 `0.45` 时，不参与本帧点击。
- Vision 捏合比例使用与 MediaPipe 相同的宽高比修正二维几何，置信度取拇指尖、食指尖、食指 MCP、掌根四点的最小值。
- 正面手掌继续使用现有 MediaPipe 图像、世界和深度概率；若 Vision 可用且明确判定分离，则阻断误点。
- 侧向手掌 `palmFacingScore < 0.45` 时，Vision 高置信度结果成为点击主证据，MediaPipe 图像距离只作为辅助，不再让错误世界深度硬性阻断真实接触。
- 双模型路径固定使用最近 5 帧至少 3 票；必须先观察到靠近过程，释放仍需连续确认，防止静态重叠误点。
- Vision 不可用、助手崩溃或网页运行时，自动回退现有 MediaPipe 路径，不关闭摄像头和光标移动。

## Electron 安全边界

- 预加载层只暴露 `detectAppleHand(jpeg, capturedAtMs)` 和显式的 `saveHandSample(sample)`，不暴露任意 IPC。
- JPEG 最大 400 KiB；时间、数组长度、坐标和置信度在预加载层、主进程和助手响应解析层分别验证。
- 主进程只接受当前可信顶层渲染帧的请求。
- Swift 助手只读取标准输入，不访问摄像头、网络或任意用户路径。
- 本地样本只能由用户点击“保存当前手部样本”后通过系统保存对话框写入；不会自动保存或上传。

## 诊断和记录

中文界面新增：

- 识别模式：双模型、MediaPipe 降级或 Vision 等待中
- Vision 捏合比例
- Vision 指尖置信度
- Vision 结果年龄
- Vision 推理耗时
- 双模型是否一致

诊断记录升级到版本 5，保存这些数值；解析器继续兼容版本 1–4。个人校准继续使用 v2，Vision 使用相同图像接触和分离边界，不再次废弃用户校准。

## 本地样本

“保存当前手部样本”写出单个 JSON 文件，包含 JPEG 的 base64、MediaPipe 关键点、Vision 关键点、置信度、宽高比、融合诊断和采集时间。文件只用于后续复现和训练专用接触分类器，界面明确标注“仅保存到本机”。

## 错误处理

- GPU 初始化失败：记录错误并使用 CPU MediaPipe。
- Swift 助手不存在、启动失败、输出损坏或退出：本次请求返回不可用，5 秒后允许重启。
- Vision 请求 250 毫秒未完成：丢弃结果，下一帧可继续；迟到响应不得覆盖更新结果。
- JPEG 编码失败：跳过本帧，不影响 MediaPipe。
- Vision 与 MediaPipe 长时间分歧：不点击，并在中文诊断显示“双模型不一致”。

## 验收

自动测试覆盖 GPU 到 CPU 回退、原生协议解析、IPC 输入限制、帧节流、Vision 坐标转换、过期与低置信度拒绝、侧向 Vision 主证据、正面分离阻断、3/5 投票、v1–v4 记录迁移、v5 回放和本地样本显式保存。

打包验收必须确认 Swift 助手存在于应用 Resources、应用能启动、界面显示双模型诊断、没有开启系统控制。现场测试正面、45°和接近 90°各五次；侧向真实捏合时 Vision 比例必须下降，若未下降则保存一份本地样本供下一轮训练，不能再通过放宽阈值掩盖模型错误。

## 非目标

本轮不引入 Python、PyTorch、云端推理或自动上传，不训练 RTMPose/自定义模型，不恢复右键、拖动、双击或滚动。
